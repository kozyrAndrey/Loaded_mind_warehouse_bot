# Loaded Mind Warehouse Bot

Бот для складских процессов Loaded Mind. Основан на HMMLS Warehouse Bot, но использует отдельную PostgreSQL-базу и отдельные настройки.

## Функции

- Все кнопки отображаются постоянной клавиатурой под полем ввода Telegram. Доступные разделы зависят от роли.
- Приёмка: новая поставка, неликвид, отбракованный товар; товар ищется в МойСклад по названию, штрихкоду или полному коду ЧЗ. В запись сохраняются количество, брак, доработка.
- Отгрузка: поиск заказа покупателя в МойСклад по цифровой части номера, привязка отдельного 31-символьного кода ЧЗ к фактической цене каждой единицы, Excel-выгрузка активных кодов и подтверждаемое удаление после вывода из оборота.
- Возвраты СДЭК и шоу-рума: документ, контрагент, товары из МойСклад, состояние, фото и ЧЗ. В возврате СДЭК бот локально считывает ФИО и трек с фото накладной, после чего сотрудник проверяет и при необходимости исправляет оба поля. Записи хранятся в PostgreSQL и отправляются в указанную тему.
- Расходники: приёмка и пересчёт без норм расхода на товар.
- Сотрудники и роли. Список сотрудников Loaded Mind пустой до добавления через бот.
- Расписание составляет руководитель склада или администратор для всех сотрудников.
- Задачи: разовые задачи на дату, регулярные шаблоны по дням недели, назначение исполнителей, дедлайны, статусы и ручная выгрузка в Telegram. Раздел доступен руководителям и администратору.
- Маркировка: выгрузка кодов для стока, комплект файлов Trend Island (CSV для УПД и Excel для 1С), дубликаты ЧЗ 58×40 и 75×120, поиск товара/кода в МойСклад. Для этикетки 75×120 поля «Заказчик» и «Производитель» берутся из дополнительных полей карточки товара в МойСклад; если они не заполнены, бот сообщит об этом.
- Полная логика ЗП и KPI старого бота. Справочник из 15 KPI взят из действующей БД HMMLS; ставки и названия можно изменить через бот. История ЗП и сотрудники HMMLS не переносятся.
- Управление модулями доступно администратору и руководителю склада.
- `/whereami` (также `/wehereami`) показывает идентификаторы чата и темы; `/whoami` показывает Telegram user_id.

Ежедневно в 09:30 по Москве бот публикует список работающих сотрудников, а в 09:35 — задачи на день. Для работы не требуется Google Sheets: файл `modules/payroll/google_sheets.py` и аналогичный файл расписания используют PostgreSQL через совместимый слой `DatabaseWorksheet`.

Сводка ежедневных отчётов склада отправляется руководителю бренда только после сохранения руководительского отчёта. В неё входят все фактически сданные ежедневные отчёты за выбранную дату; расписание и полнота сдачи на отправку не влияют.

## Конфигурация

Создайте `.env` по примеру `.env.example`. Секреты не добавляются в Git. Для первого запуска укажите `BOOTSTRAP_ADMIN_IDS` с Telegram user_id владельца: только если таблица сотрудников пуста, бот добавит этого пользователя как администратора. Далее сотрудники и ставки ведутся из интерфейса бота.

Установите зависимости из `requirements.txt`, создайте отдельную PostgreSQL-базу и запустите `python bot.py`. При старте необходимые таблицы создаются автоматически.

Для OCR накладных СДЭК и этикеток шоурума на сервере нужен Tesseract с русским и английским языками (`tesseract-ocr`, `tesseract-ocr-rus`, `tesseract-ocr-eng`). Бот предлагает распознанные ФИО и трек-номер СДЭК либо необязательный номер заказа шоурума; сотрудник проверяет и может исправить каждое поле. Если OCR недоступен или не распознал поле, доступен ручной ввод.

Отчёт о возврате публикуется подписью к единственному фото или первому фото альбома. При превышении лимита подписи продолжение текста отправляется отдельно без обрезания; каждые 2–10 фото группируются в альбом согласно ограничениям Telegram.

В Telegram добавьте бота в нужную группу, вызовите `/whereami` внутри каждой темы и укажите полученные ID в `.env`. До заполнения ID возвраты сохраняются в базе, но в тему не отправляются.

## Маркировка и Trend Island

«Выгрузка кодов для стока» запрашивает точное название документа «Вывод из оборота» в МойСклад и формирует Excel без заголовка — по одному КИЗ в строке.

«Файлы Trend Island (УПД + 1С)» сначала выбирает тип цены: `Старая цена` при действующих скидках или `Цена продажи` без скидок. Затем бот получает позиции и КИЗ документа, формирует CSV для УПД и Excel на основе `resources/trend_island_1c_template.xlsx`. Справочник GTIN и немаркируемых товаров первоначально загружается из `resources/honest_sign_products.csv`; существующие записи в базе при перезапуске не перезаписываются.

Для работы обоих сценариев необходим `MOYSKLAD_TOKEN`. Типы цен и параметры Excel можно переопределить переменными `MOYSKLAD_SALE_PRICE_TYPE`, `MARKING_ONE_C_RETAIL_PRICE_TYPE`, `MARKING_ONE_C_DEFAULT_GENDER`, `MARKING_ONE_C_CONSIGNOR` и `MARKING_ONE_C_TEMPLATE_PATH`.
